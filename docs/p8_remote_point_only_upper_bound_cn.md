# P8 remote point-only 上限探索

## 目标

P7 projection aux 多任务分解目前没有稳定学出可用的 remote 投影参数，因此先回到最直接的目标：只优化 remote pointmap 回归，探索“给定多张普通视角上下文时，remote 点云恢复能做到什么上限”。

本阶段不再把 height / slope / direction / offset 作为主线指标。判断标准以 remote 点云误差和可视化为主。

## 训练原则

- 只保留 remote pointmap loss，关闭 projection aux、MoGe prior、height aux、branch consistency。
- 普通视角作为上下文输入，先测试 4 个普通视角，再扩展到 8 个普通视角。
- 优先使用 private remote point head，避免 remote 对普通视角 point/depth head 造成过强干扰。
- 先用 chicago + newyork 快速验证趋势；如果明确优于已有结果，再跑全城市长训练。
- checkpoint 控制为 final / best slim，避免保存大量中间权重。
- 每个关键模型都对 Seattle 493 和 NewYork 461_1 导出 mixed 点云和 remote-only 点云。

## 2026-06-13 补充结论：joint 训练为什么之前失败

这次定位到一个关键问题：`REMOTE_COMPARE_GT_IN_VIEW0_ONLY=true` 会让 remote pointmap loss 使用 `remote_pointmap_view0` 作为 GT，但 direct remote point head 的预测仍处在 remote/world pointmap 域。如果没有同时把预测也变换到 view0 frame，这就是监督域错配。错误设置下，即使 remote head 和 remote aggregator 都从 remote-only checkpoint 初始化，joint epoch0 的 `rs_pointmap_loss` 仍会跳到 `~2.33`，说明训练一开始就在用错误坐标监督污染参数。

修正为 `REMOTE_COMPARE_GT_IN_VIEW0_ONLY=false` 后，同一个 private remote aggregator 结构在 20 个四卫星训练样本上恢复到 remote-only PLY 上界附近。这给出一个可靠方向：后续正式 joint 训练必须同时满足：

- direct remote pointmap 监督使用 world/remote GT，不使用 view0 GT，除非预测也显式变换到 view0；
- remote 视角使用独立 `remote_aggregator`，避免 ordinary 视角和 remote 视角在 shared aggregator 里互相拉扯；
- ordinary path 继续保留小权重 aerial loss，用于保护 mixed 点云，但 remote 分支的主监督仍是尺度无关 remote pointmap loss；
- 导出和评测必须启用 private aggregator，否则 PLY 结果会退回旧路径，不能反映训练好的 remote 分支。

## 2026-06-14 补充结论：正式 joint 训练已有突破

基于上述修正继续跑全城市 joint 训练后，NewYork `remote_pointmetric20` 的 joint remote 点云指标第一次明显突破此前平台：`rs_point_l1_scale_aligned=7.120`，`rs_point_abs_rel_scale_aligned=0.0792`。此前多组 P8 point-only / joint 实验长期停在 `rs_point_l1_scale_aligned≈95.5`、`rs_point_abs_rel_scale_aligned≈1.0`，因此这不是普通波动，而是结构和监督域修正后的有效提升。

继续两轮低 LR 后，当前最好结果更新为 `rs_point_l1_scale_aligned=6.628`、`rs_point_abs_rel_scale_aligned=0.0739`、`rs_height_mae_affine=6.030`。这说明正式 joint 训练可以继续优化 remote 点云，但高 LR 会明显退化，当前策略必须保护已学 remote 解。

需要注意两个细节：

- benchmark 脚本和导出脚本都必须识别 `remote_aggregator.*` 并启用 `use_remote_private_aggregator=true`；否则会加载同一个 checkpoint 但走旧模型路径，指标不可信。
- 当前训练日志里的 raw metric 仍约 `400`，但 scale-aligned benchmark 大幅改善，说明最终评价仍应以尺度无关 remote 点云指标为主，不能单看 raw metric。

下一步更合理的实验不是回到 projection aux，而是在这个 P8 结构上做 ablation：严格冻结 ordinary shared patch LR、加长 epoch、评估全部城市/多 provider、检查 Seattle 493 和 NewYork 461_1 的 PLY 高楼形状，并测试是否需要高楼像素加权或鲁棒 point loss。

## 待验证问题

- 4 个普通视角是否已经足够，还是 8 个视角能显著改善 remote 几何：当前 8-view 全城市未改善。
- no-crop 是否比 random remote crop 更稳定：当前 no-crop 能收敛 normalized loss，但 remote benchmark 仍不变，crop 不是首要瓶颈。
- low trunk LR 是否足够：midtrunk 实验证明 trunk 可被优化，normalized loss 明显下降，但 raw/scale-aligned remote 点云误差不随之下降。
- 当前 remote 标签噪声下，是否需要更鲁棒的 point loss 或 top-percent 排除策略：仍需验证，但单纯降低 normalized pointmap loss 已证明不够。
- 已测试 top5 + scale-aligned 绝对坐标项：没有改善，说明只做 outlier 排除和最优全局尺度 L1 不足以对齐最终 remote 几何指标。
- 已测试 axis-normalized / unclamped scale-aligned / shape-normalized：一个会伤害 normalized point loss，后两个机制正常但指标不动。
- 已测试 shared 原始 point head：没有突破，说明 private remote point head 不是主要瓶颈。
- 已测试 frozen trunk 只训 remote head：RS-only 仍无突破，但 joint scale-aligned 略降到 `94.862`，说明“训练 loss 更低”不必然等价于“joint remote 点云更好”，主干/ordinary geometry 被破坏可能会抵消 remote head 的收益。
- 已新增 RS pointmap 相对误差指标：`rs_point_abs_rel` 等价于普通视角 `pointmaps_abs_rel` 的未对齐版本；`rs_point_abs_rel_scale_aligned` 是中心化 + 全局尺度对齐后的相对误差，后续应优先和 `rs_point_l1_scale_aligned` 一起看。frozen-head best 的 joint `rs_point_abs_rel_scale_aligned=0.9956`，说明 L1 的小幅降低没有带来可靠形状突破。
- 已测试高楼训练集 overfit：即使只在 8 个高楼训练 scene 上训练 160 epoch，loss 仍明显波动，final 未稳定低于低楼 overfit 水平。这说明高楼失败不是单纯数据量不够或全量训练没跑久，而是当前 remote pointmap loss 对高层/高动态范围局部结构的监督不够可靠。
- 已测试 NY/Chicago 四卫星 joint overfit：扩大同一 location 的卫星 provider 多样性并恢复小权重 ordinary/aerial loss 后，训练仍出现明显低点和高点交替，final 反弹。该结果支持一个判断：仅增加 provider 数量和小权重普通视角约束，不能单独解决高楼 remote 点云不稳定问题；但它提供了更完整的训练集可视化对照，可直接比较每个 provider 的 GT 与预测 remote 形状。

## 当前阶段结论

多组 point-only 实验共同说明：remote point head 不是完全不能训练，归一化 pointmap loss 能够稳定下降；但是当前训练目标和最终 remote 点云 benchmark 存在明显脱钩。增加普通视角数量、扩大到全城市、提高 aggregator 学习率、关闭 aerial loss、从原始 VGGT 重新训练并拉长到 16 epoch，都没有让 NewYork `remote_pointmetric20` 的 scale-aligned remote 点云误差从约 `95.5` 的平台上明显下降。

因此，继续简单加 epoch / 加普通视角 / 提高 trunk LR 的收益预计很低。remote-dominant warmstart 和 remote-only 从原始 VGGT 重训都改善了内部验证，但没有改善正式 NewYork `remote_pointmetric20` 的尺度无关点云指标，因此目前不能把普通视角 loss 或 warmstart 坏局部解视为主要瓶颈。

shape-normalized 和 shared point head 实验也没有推动 `remote_pointmetric20`，因此 point-only 分支的主要问题更可能不是训练轮数、warmstart、普通视角数量、简单 loss 权重或 private head 初始化，而是 remote 输入条件、坐标表达/归一化目标与 benchmark 的脱钩，或者 remote image 本身不足以从当前 token 路径恢复稳定 3D。

frozen trunk 诊断补充了一点：完全冻结主干时，remote head 的内部 loss 明显更差，但 joint `rs_point_l1_scale_aligned` 反而有小幅改善。这说明此前可微调 trunk 实验可能把 normalized remote loss 压低了，却同时扰动了普通视角/全局几何，使 joint benchmark 收益被抵消。因此后续不能只追求 remote normalized loss，还要测试更保守的 trunk 适配、低重叠采样、以及更贴近 joint benchmark 的验证方式。

高楼 overfit 诊断进一步说明：当前结构对低楼/中低楼有一定记忆能力，但面对高层建筑时不稳定。主要问题不是“完全不会训练”，而是高楼点云的 z 范围和投影 xy 位移更大，remote 标签有效区域和高层区域占比更小，普通逐像素 L1 容易被地面/低层区域主导；同时普通视角随机变化时，模型没有显式机制把 oblique view 中的高层侧面证据稳定绑定到 remote 像素。因此，高楼场景中会出现某些 batch loss 很低、换一组普通视角或换一个 location 又反弹的情况。

后续应继续围绕以下方向推进：

- 测试低重叠 / 零重叠普通视角采样，判断 ordinary context 的采样方式是否影响 joint remote 几何。
- 测试更保守的 trunk 适配策略，在尽量不破坏普通视角几何的前提下提升 remote head。
- 使用尺度无关但和 benchmark 一致的 remote point loss，减少训练 normalized loss 与 raw/centered/scale-aligned 指标脱钩。
- 加入鲁棒点云损失或有效点筛选，降低 remote 标签局部噪声对高层建筑和稀疏区域的影响。
- 对高层区域加权或分桶采样，例如按 GT z 分位数、height gradient、building mask/edge 对高楼像素提高权重，避免训练目标被地面区域平均掉。
- 对 remote-only 与 joint 输入分别评估，避免普通视角上下文只改善 pose/aerial 指标而不改善 remote 几何。
